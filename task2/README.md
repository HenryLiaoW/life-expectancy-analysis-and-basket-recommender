## 🎯 Overview

A Python-based recommendation system that analyzes customer purchasing patterns from supermarket transaction data using graph-based data structures and co-occurrence analysis.

**Key Features:**
- Single item recommendations
- Frequent product pair discovery
- Co-purchase frequency analysis
- Basket-based recommendations (extension)
- Real-time dynamic updates (extension)
- Graph visualization (ASCII & DOT export)

## 📊 Implementation Highlights

- **Data Structure**: Adjacency list (dict-based) for efficient graph representation
- **Algorithm**: Co-occurrence counting with heap-based Top-K selection (O(E log k) vs O(E log E) full sort)
- **Design Pattern**: Two-layer architecture (Graph + Recommender) with dependency injection
- **Development Method**: Test-Driven Development (TDD)
- **Test Coverage**: 44 comprehensive tests (100% pass rate)
- **Visualization**: Pure Python ASCII art + DOT format export

## 🏗️ Architecture

### Two-Layer Design

```
┌─────────────────────────────────────┐
│   Recommender Engine Layer          │  ← Business logic
│   - recommend_for_item()            │
│   - get_most_frequent_pairs()       │
│   - check_co_purchase()             │
│   - recommend_for_basket()          │
│   - update_with_transaction()       │
└─────────────────┬───────────────────┘
                  │ uses
                  ↓
┌─────────────────────────────────────┐
│   Graph Adjacency List Layer        │  ← Data structure
│   - build_from_csv()                │
│   - add_transaction()               │
│   - get_neighbors()                 │
│   - get_top_neighbors()             │
│   - get_edge_weight()               │
│   - visualize_subgraph()            │  ← Visualization
│   - export_to_dot()                 │
└─────────────────────────────────────┘
```

### Key Design Decisions

1. **Adjacency List over Matrix**
   - Sparse graph (45% density)
   - O(degree) neighbor queries vs O(n)
   - Dynamic edge insertion: O(1) vs O(1)
   - Space: O(edges) vs O(n²)

2. **Heap-Based Top-K Selection**
   - Uses size-k heap for frequent pairs: O(E log k)
   - Avoids full sort O(E log E) when k << E
   - For k=10, E=6260: 20K ops vs 81K ops (4× faster)
   - Critical for analytical queries with small k

3. **Stable Sorting**
   - Primary: Count descending (-count)
   - Secondary: Name ascending (name)
   - Ensures reproducible results

3. **Graceful Degradation**
   - Missing items → return empty []
   - Invalid queries → return False/0
   - Consistent with Task 1 design

4. **Symmetric Graph**
   - Undirected edges (A→B implies B→A)
   - Both directions updated simultaneously

### Computational Complexity

| Operation | Time Complexity | Space Complexity |
|-----------|----------------|------------------|
| Build graph | O(T × k²) | O(V + E) |
| Single item recommend | O(d log d) | O(d) |
| Top-k pairs | O(E log k) | O(E) |
| Co-purchase check | O(1) | O(1) |
| Basket recommend | O(b × d) | O(V) |
| Dynamic update | O(k²) | O(1) |

Where:
- T = number of transactions
- k = average basket size
- V = number of vertices (items)
- E = number of edges
- d = average degree
- b = basket size

### Scalability Considerations

**Strengths:**
- O(1) edge weight lookups
- Efficient for moderately connected graphs
- Dynamic updates without full rebuild

**Limitations:**
- O(E) memory for all edges
- Top-k pairs requires full edge iteration
- Not optimized for extreme sparsity (<10% density)

## 📋 SOLID Principles Analysis

### Single Responsibility Principle (SRP)

**Definition**: Each class should have one, and only one, reason to change.

| Class | Single Responsibility | Evidence |
|-------|----------------------|----------|
| `GraphAdjacencyList` | Graph data structure operations | `build_from_csv()`, `add_transaction()`, `get_neighbors()` - only graph manipulation |
| `RecommendationEngine` | Business logic for recommendations | `recommend_for_item()`, `check_co_purchase()` - domain rules only |
| `SupermarketCLI` | User interface and interaction | `display_menu()`, `handle_choice()` - presentation layer only |

**Code Evidence**:
```python

class GraphAdjacencyList(Graph):
    """ONLY handles graph data structure - no business logic"""
```

### Open/Closed Principle (OCP)

**Definition**: Software entities should be open for extension but closed for modification.

**Implementation**: Abstract `Graph` interface allows new implementations without changing `RecommendationEngine`.

```python
# graph_interface.py:L10-30
class Graph(ABC):
    @abstractmethod
    def get_neighbors(self, item: str) -> Dict[str, int]: ...

# Can extend without modifying existing code:
class GraphMatrix(Graph):           # New implementation
    def get_neighbors(self, item): ...

class GraphEdgeList(Graph):         # Another implementation
    def get_neighbors(self, item): ...

# RecommendationEngine works with ANY Graph implementation:
engine = RecommendationEngine(graph=GraphMatrix())  # No code changes needed
```

**Evidence Location**: `src/graph_interface.py:L10-90`, `src/recommendation_engine.py:L15-25`

### Liskov Substitution Principle (LSP)

**Definition**: Subtypes must be substitutable for their base types.

**Implementation**: Any `Graph` subclass can replace `GraphAdjacencyList` without breaking functionality.

```python
# All Graph implementations honor the same contract:
def process_recommendations(graph: Graph):  # Accepts ANY Graph subclass
    engine = RecommendationEngine(graph=graph)
    return engine.recommend_for_item("milk", top_k=5)

# These all work identically:
process_recommendations(GraphAdjacencyList())
process_recommendations(GraphMatrix())      # Hypothetical alternative
```

**Test Evidence**: `tests/test_recommendation_engine.py:L15-40` - tests use abstract interface, not concrete class

### Interface Segregation Principle (ISP)

**Definition**: Clients should not be forced to depend on interfaces they don't use.

**Implementation**: `Graph` interface provides only essential methods needed by `RecommendationEngine`.

```python
# Minimal interface - no bloat
class Graph(ABC):
    def get_neighbors(...)      # Required for recommendations
    def get_edge_weight(...)    # Required for frequency checks
    def has_item(...)           # Required for validation
    # NO unnecessary methods like: get_diameter(), find_shortest_path(), etc.
```

**Evidence**: `src/graph_interface.py:L10-90` - only 8 essential methods defined

---

### Dependency Inversion Principle (DIP)

**Definition**: High-level modules should depend on abstractions, not concrete implementations.

**Before Refactoring** (Violated DIP):
```python
# recommendation_engine.py (old)
from task2.src.graph_adjacency_list import GraphAdjacencyList  # Concrete dependency!

class RecommendationEngine:
    def __init__(self):
        self.graph = GraphAdjacencyList()  # Tightly coupled
```

**After Refactoring** (Follows DIP):
```python
# recommendation_engine.py (current)
from task2.src.graph_interface import Graph  # Abstract dependency!

class RecommendationEngine:
    def __init__(self, graph: Optional[Graph] = None):  # Dependency injection
        self.graph = graph if graph is not None else GraphAdjacencyList()
```

**Evidence**: Git commit shows DIP refactoring; `src/recommendation_engine.py:L15-25`

## 📐 Additional Design Principles

### KISS (Keep It Simple, Stupid)

- **Dict-based adjacency list** instead of custom graph classes
- **Substring matching** for suggestions (no NLP/fuzzy algorithms)
- **Pure Python** - no external libraries

### YAGNI (You Aren't Gonna Need It)

- **No premature optimization** (e.g., caching, indexing)
- **No unused features** (e.g., shortest path, graph diameter)
- **No over-engineering** (e.g., plugin architecture, config files)

### Separation of Concerns

```
┌─────────────────────────┐
│   Presentation Layer    │ ← CLI (user interaction)
│   (SupermarketCLI)      │
└────────────┬────────────┘
             │
┌────────────▼────────────┐
│   Business Logic Layer  │ ← Engine (recommendations)
│   (RecommendationEngine)│
└────────────┬────────────┘
             │
┌────────────▼────────────┐
│   Data Structure Layer  │ ← Graph (storage)
│   (GraphAdjacencyList)  │
└─────────────────────────┘
```

Each layer can be tested independently without dependencies on others.
